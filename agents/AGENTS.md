## 応答スタイル
- 最終回答は簡潔に。冗長な前置きは不要
- コードの説明は日本語、コード自体やコミットメッセージは英語
- 曖昧な指示には仮定を明示した上で進めてOK。逐一確認しない

## 作業ポリシー
- 破壊的な操作（rm -rf、force push、DBのマイグレーション実行等）は必ず事前に確認
- 新しい依存関係の追加は確認してから
- git commit は指示があるまで実行しない（add/diffの確認までは可）

## コーディング規約
- インデントはスペース2つ
- 型がある言語では極力anyを避ける
- エラーハンドリングは握りつぶさず、ログに残すか呼び出し元に伝播させる
- レビュー時はまずセキュリティとテストの有無を確認してから可読性を見る

## テスト
- コード変更後は関連するテストを実行してから完了報告する
- テストがないコードを変更した場合はテスト追加を提案する

## やらないこと
- 使われていないコードを勝手に削除しない（確認してから）
- 大規模なリファクタは提案のみに留め、実行は指示があってから
